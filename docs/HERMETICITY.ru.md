# Герметизация runtime зоны — дизайн и решения, которые нужно принять

English: [HERMETICITY.md](HERMETICITY.md) · Связанные документы:
[LEAK-MODEL.md](LEAK-MODEL.md) («Открытые каналы»),
[CONTAINERS.ru.md](CONTAINERS.ru.md) §6, ROADMAP M3 (герметизация, брокер, X11).

**Статус: решено (владелец, 2026-09-17), реализация идёт** — решения в §7.
`cellward doctor` называет каждый канал ниже предупреждением, пока он не
закрыт, и по пути — каждый unix-сокет, к которому программа зоны может
подключиться и который не её собственный (`docs/LEAK-MODEL.md` §18).

## 1. Что открыто сегодня

Программа, запущенная в зоне БЕЗ песочницы (без `--sandbox`/`--fs-sandbox`),
видит в mount namespace зоны то же, что любая программа хоста:

| канал | что он даёт программе в зоне | LEAK-MODEL |
|---|---|---|
| `/run/user/<uid>/bus` (сессионная шина) | `org.freedesktop.systemd1` → `StartTransientUnit`: любой процесс СНАРУЖИ зоны, в сети хоста; порталы (`OpenURI` открывает ссылку на хосте); Secret Service (все пароли связки ключей); D-Bus-API любой другой программы | §1, §2 |
| `/run/user/<uid>/systemd/private` | тот же `systemd --user`, без D-Bus | §1 |
| `/run/dbus/system_bus_socket` | NetworkManager (настоящие интерфейсы, SSID, адреса), hostname1, resolve1, machined: деанон без единого пакета | §3 |
| `/tmp/.X11-unix/X*`, `DISPLAY` | X-сервер хоста: клавиатура, экран и буфер обмена всей машины | §7 |

Топология сети не закрывает ни один: это unix-сокеты, а не интерфейсы.
Закрывает только mount namespace — песочница так уже делает для программ в ней,
и цена там измерена: «только порталы, уведомления и трей».

## 2. Форма решения

В mount namespace зоны (один раз при подъёме зоны, чтобы это получила каждая
программа зоны, а не отдельный запуск):

1. **tmpfs поверх `/run/user/<uid>`** — после `docs/LEAK-MODEL.md` §13 у
   КАЖДОЙ зоны, и собственный сокет композитора `wayland-*` с его IPC назад не
   биндятся никогда; ограниченный сокет Wayland делает на запуск `wl-sandbox`
   на хосте, в каталоге зоны `vpn-zones/wayland/<зона>/`; слушает там
   посредник запуска, он же рисует вокруг окон программы обводку цвета зоны
   (`docs/WINDOW-FRAME.md` §8) своими объектами, которых программа назвать не
   может, и новых глобалов ей не показывает. Цвет, толщина и выключатель
   рамок — в `~/.config/vpn-zones` и состоянии зон, куда зона не пишет.
   Герметичной зоне
   назад биндятся PipeWire — свой ограниченный сокет (контекст безопасности,
   который помощник зоны отдаёт PipeWire, и наша политика WirePlumber: свои
   потоки, выходы, микрофоны только при `yes`, никогда монитор и свои связи;
   без политики PipeWire нет вовсе; сырой `pipewire-0` хоста — только зоне,
   объявленной менеджером звука, `cellward audio-manager`; откуда WirePlumber
   и PipeWire берут скрипты и фрагменты в доме — `~/.config/pipewire`,
   `~/.config/wireplumber`, `~/.local/share/wireplumber`,
   `~/.local/state/wireplumber` — в зоне только для чтения и создаются
   заранее, иначе программа подменила бы политику;
   `docs/LEAK-MODEL.md` §20),
   PulseAudio (сокет фильтра `pulse-filter`: список разрешённых команд, без
   записи монитора — `docs/LEAK-MODEL.md` §17) и два наших сокета —
   **фильтрованная сессионная шина**
   (`xdg-dbus-proxy`) и **брокер**. `systemd/private` назад не биндится.
2. **tmpfs поверх `/tmp/.X11-unix`** и `DISPLAY` убран из окружения запуска;
   контейнер с разрешением `x11` получает свой `xwayland-satellite` (решение А).
3. **Системная шина**: один из вариантов B1–B3 ниже.

## 3. Решение C — сессионная шина и брокер

Фильтр с правилами песочницы (порталы рабочего стола и документов по имени, `Notifications`,
`StatusNotifierWatcher`) для КАЖДОЙ программы зоны ломает — по тому, зачем
программам шина:

| ломается | кто заметит |
|---|---|
| Secret Service / KWallet / GNOME Keyring | браузеры переходят на незашифрованное хранилище паролей или спрашивают пароль; почтовые и чат-клиенты теряют сохранённые входы |
| MPRIS (`org.mpris.MediaPlayer2.*`, нужен `--own`) | медиа-клавиши и виджет плеера в оболочке не видят плееры в зоне |
| значки трея у Electron и Qt (сперва занимают `org.kde.StatusNotifierItem-<pid>-<n>`) | значка нет, а программу, которая при закрытии прячется в трей, оттуда не вернуть — с 2026-09-24 разрешено правилом `--own=org.kde.StatusNotifierItem-*` нашего пропатченного фильтра: только занять имя, и ничего больше |
| методы ввода IBus / fcitx5 | набор во второй раскладке через метод ввода перестаёт работать в программах зоны |
| глобальные хоткеи KDE (`org.kde.kglobalaccel`) | хоткеи, зарегистрированные программами зоны, ничего не делают |
| запись dconf / GSettings (`ca.desrt.dconf`) | GTK-программы не сохраняют настройки (держат в памяти) |
| `systemd --user` | **так и задумано** — в том числе сегодняшнее делегирование запуска из зоны (`launch.rs`, шаг 1), отсюда брокер |
| D-Bus-активация других программ | программа зоны не может запустить программу хоста по имени — тоже так задумано |

Каждую строку можно вернуть контейнеру по отдельности (`permissions.dbus`, как
`finish-args` у Flatpak) — кроме `systemd1`, который и есть побег.

**Брокер** заменяет делегирование: один сокет на зону (цель — один на запуск контейнера, [PERMISSIONS.md](PERMISSIONS.md) §11.9), один глагол — «открыть
вот это» (URI, файл, переданный дескриптором, id ярлыка). Сторона хоста знает,
какая зона просит, и отвечает:

- цель назначена тому же контейнеру → запустить там же, без диалога;
- зона заперта → только тот же контейнер;
- иначе → пикер, с «просит зона X» в вопросе.

**Выбор из зоны (2026-09-25).** Пикер, которого запускает программа в зоне (открытая ею
ссылка), не видит ни одной зоны — состояние проекта от зон спрятано, — а окно, нарисованное
зоной, могла бы нарисовать и её программа. Поэтому он спрашивает брокер (`VZP1`, app-id и
команда), и брокер показывает окно запуска на хосте (`vpn-zone-pick --from-zone`): в
заголовке — спросившая зона, команда — по слову в строке, выбрана спросившая зона, запертой
зоне предложена только она сама, «всегда» нет (зона выбирает, чьим ярлыком назвать окно).
Без окна не решается ничего — закрепление или запущенная копия только выбирают, с чего
окно начнёт. Окно ничего не принимает — ни клавиш, ни щелчков, ни выбора, — пока человек
не пробудет в покое `dialog::TOO_FAST` при окне в фокусе: каждая клавиша (и та, что взял
виджет), каждое нажатие мыши, возвращение фокуса и смена выбора начинают отсчёт заново.
Enter запускает только в спросившей зоне; другая сеть — щелчок по кнопке с её именем;
цифры не выбирают ничего. Команда — отдельным блоком, по слову с номером, с программой,
как её находит хост (с пометкой, если она не из стора); сеть хоста — последней в списке;
новых контейнеров в этом окне нет. Программу брокер находит один раз, до окна:
окно показывает этот абсолютный путь, и запускается именно он — `run` ничего не ищет заново
по PATH, где ссылку в доме могли перенаправить, пока окно открыто; оболочка или
интерпретатор помечены как «запускает любую команду», программа не из стора — как
подменяемая. Вопрос без ответа закрывается через две минуты. Зону, которая спрашивает
снова и снова, спрашивают не чаще четырёх раз в минуту и не спрашивают 15 с после «нет»;
запрос длиннее 64 КиБ или с app-id длиннее 255 байт отклоняется целиком; срока на
приход запроса нет (2026-09-26, было 5 с), молчащее соединение держит слот своей зоны:
одна зона держит не больше четырёх запросов разом (всего — 64) и пишет в
журнал переходов не больше 30 строк в минуту (ревью
2026-09-25; оно же нашло, что сокет, переданный брокеру systemd, наследовали все
запущенные им программы, — теперь он закрывается при exec). Ответ возвращается аргументами `run`;
брокер проверяет, что это слово в слово команда запроса (а из запертой зоны — сама эта
зона) и что ответ пришёл не раньше, чем окно можно было прочитать, и запускает. Окно и есть
вопрос: второго нет. Контейнер сети хоста (`unconfined` в `VPN_ZONE_CURRENT`) для брокера
не зона и остаётся со своим пикером, как и зона, которой некого спросить.

**«Всегда» (2026-09).** У вопроса три ответа: разрешить, *всегда*, отказать. «Всегда»
запоминается как зона → сеть → программа в `~/.config/vpn-zones/broker-always`, по строке
`откуда<TAB>куда<TAB>программа`, и следующий такой запуск идёт без вопроса. Программа —
первое слово команды, как его находит хост: ссылки каталога развёрнуты, собственное имя
сохранено (`touch` и `cat` — ссылки на один coreutils), и «всегда» предлагается, только
когда и этот путь, и файл, которым он в итоге оказывается, лежат в сторе, куда программа
из зоны ничего не запишет: программу из `~/.local/bin` программа в зоне могла бы подменить,
и «всегда» стало бы постоянной дверью. Имени, которым запуск называет себя (app-id),
брокер не верит — его присылает сама просящая программа.

Внутри зоны `xdg-open`/`$BROWSER` ведут к клиенту брокера, а `OpenURI`/`OpenFile`
портала вырезаются из прокси шины (правила `--call`), чтобы GTK/Qt падали на
`xdg-open`. Firefox и GTK под `/.flatpak-info` зовут портал и НЕ падают на
`xdg-open` — сначала нужна портал-совместимая замена `OpenURI`; это и есть
исследовательская часть.

**Предлагаемый порядок** (его же рекомендует nix-cm-eb): прототип за флагом
зоны `hermetic = true`, ВЫКЛЮЧЕННЫМ по умолчанию, доказанный в VM «злым
хостом» — путь `systemd --user`, считающий вызовы `StartTransientUnit`,
портал, пишущий в лог, кто его звал, маячок на loopback хоста, — и только потом
умолчание, а таблица выше — список того, с чем соглашается владелец.

## 4. Решение B — системная шина

| вариант | как | цена |
|---|---|---|
| B1 | tmpfs поверх `/run/dbus` в зоне | UPower (батарея), ингибиторы logind (плеер, не дающий экрану погаснуть), апплеты NetworkManager внутри зон перестают работать |
| **B2 (рекомендую)** | `xdg-dbus-proxy` для системной шины: `login1` и `UPower` разрешены, `NetworkManager`, `hostname1`, `resolve1`, `machined`, `timedate1` запрещены | один процесс прокси на зону, запускается и супервизится держателем зоны, как pasta |
| B3 | как есть, `warn` в `doctor` | NetworkManager отвечает любой программе зоны, в каких сетях машина |

## 6. Что не обсуждается

- В песочнице всё это уже есть и остаётся.
- Переменные окружения границей не являются (`unset DBUS_SESSION_BUS_ADDRESS`
  ничего не меняет: пути сокетов общеизвестны). Закрывает только mount.
- Ни один пункт не меняет сеть: пакет никуда нового не уходит; меняется то,
  каких служб хоста программа зоны может попросить действовать за неё.

## 7. Решения (владелец, 2026-09-17)

- **А — X11: вариант А — сделано.** В зонах закрыт по умолчанию: tmpfs поверх
  `/tmp/.X11-unix` в mount namespace зоны и никакого `DISPLAY` в запуске.
  Контейнер с разрешением `x11` получает свой `xwayland-satellite`. Дыры
  `x11 = "host"` нет. То же на зону, для зон без контейнеров:
  `cellward x11 <зона> on` или `zoneX11 = [ "<зона>" ]`.
- **B — системная шина: B2, суженный — сделано.** `xdg-dbus-proxy` на зону; `UPower`
  разрешён; `login1` — только `Inhibit` и чтение свойств, без списка сессий и
  управления питанием; `NetworkManager`, `hostname1`, `resolve1`, `machined`,
  `timedate1` запрещены.
- **C — сессионная шина и брокер.** Сначала прототип за флагом зоны
  `hermetic`, доказанный «злым хостом» в VM — **прототип сделан**
  (`cellward hermetic <зона> on`); дальнейшее — ещё нет. Потом:
  1. `hermetic` включён по умолчанию; выключение — явное и на одну зону
     (зона, программы которой законно управляют `systemd --user`, например
     агенты, запускающие VM-проверки через `systemd-run --user`).
     **Сделано, и умолчание перевёрнуто (2026-09):**
     `hermetic.default` и `hermetic.exceptions` в модуле,
     `cellward hermetic --default on (по умолчанию)|off` и
     `cellward hermetic <зона> default (как у всех зон)|on|off` локально. Что важнее: зона из
     `hermetic.exceptions` (обратное `hermetic.default`, который модуль требует
     вместе с ними), затем своя настройка зоны, затем `hermetic.default`, затем
     локальное умолчание, затем вкл. Открывает только `off`: пустой маркер
     прототипа, нечитаемый и с любым другим содержимым значат вкл. Держатель
     решает один раз, при подъёме зоны; `status --json` показывает
     `defaults.hermetic` и `networks[].hermetic`, у каждого — источник;
  2. разрешения шины — из манифеста программы на Flathub (`finish-args`:
     `--talk-name`, `--own-name`, `--system-talk-name`), когда он есть, чтобы
     фильтр не ломал известные программы; `permissions.dbus` — для остальных;
  3. Secret Service — как портал Secret у Flatpak: свой ключ контейнера,
     никогда вся связка ключей хоста;
  4. MPRIS и методы ввода (IBus, fcitx) разрешены по умолчанию; запись dconf и
     глобальные хоткеи KDE — разрешением контейнера.
- `own` для всего (решение №2 из CONTAINERS §12) — это песочница, то есть
  Flatpak-подобная изоляция и без `hermetic`; флаг закрывает остальное:
  контейнеры-слои, основной профиль, запуски без песочницы.
