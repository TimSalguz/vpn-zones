# Роадмап vpn-zones

Цель: универсальный rootless-инструмент запуска программ в сетевых зонах
(VPN, прокси, существующие интерфейсы, офлайн) с контейнерами данных и
песочницами — с прицелом на публикацию в nixpkgs.

Ядро планируется переписать на Rust одним статическим бинарём: это открывает
seccomp (BPF-фильтр генерируется только кодом), настоящие тесты, парсинг
манифестов Flathub и структуру
«пакет + тонкий модуль», которую примут в nixpkgs. Переписывание — «стренглером»:
bash-версия остаётся рабочей до подтверждённого паритета. Спецификация
накопленного поведения — [docs/GOTCHAS.md](docs/GOTCHAS.md).

Приоритет №1 на всех этапах — герметичность: никаких утечек DNS, IPv6 и
трафика мимо туннеля, fail-closed по умолчанию. Пункты, закрывающие утечки
(killswitch-заплатки M0, фаерволл/DNS/IPv6 в M3, seccomp в M2, leak-тесты в
M5), имеют преимущество перед удобствами.

Порядок этапов — приоритет, а не жёсткая очередь: сетевые этапы (M3–M5) могут
идти параллельно песочнице (M2).

## M1 — Rust-ядро (паритет с bash-версией)

Принцип этапа: минимум shell (инъекции), ноль Python/C (достигнуто: оба
python-скрипта и программа на C поглощены крейтом) — shell остаётся только
тонкими обёртками до полного паритета.

- [x] заведён крейт `rust/`; разбор конфигов WG/AWG вынесен в него: CRLF, пустые
      `I1`–`I5`, `Address`/`DNS`/`MTU`/`Endpoint` (все три формы), текст для
      `setconf`, автодетект обфускации — с юнит-тестами на каждую граблю из
      `docs/GOTCHAS.md` §4. Зоны им ещё не пользуются: конфиги по-прежнему
      разбирает bash
- [x] оба python-скрипта поглощены крейтом и удалены — Python в проекте больше
      нет: `vpn-profile-run.py` → `vpn-zone-core profile-run` (overlay-слои
      контейнера данных, сброс ambient capabilities, жизненный цикл одноразового
      контейнера), `vpn-zone-sync.py` → `vpn-zone-core sync` (генератор
      `.desktop`), с юнит-тестами на грабли §5 и §10. Обоих зовёт bash-скрипт
      `vpn-zone`: жизненный цикл зоны, `run`/nsenter и реестр запусков всё ещё
      на нём
- [ ] один бинарь `vpn-zone`: жизненный цикл зоны (unshare/newuidmap, netlink,
      pasta), `run`/nsenter, реестр запусков с блокировками — поверх уже готовых
      разбора конфигов и слоёв контейнера
- [ ] внутренняя архитектура — сразу двухнеймспейсная по `docs/LEAK-MODEL.md`:
      сокет WireGuard в uplink-ns, в app-ns только lo + туннель (паритет —
      о CLI и поведении, не о внутренностях)
- [ ] живость процессов в реестре — по PID + starttime из `/proc/<pid>/stat`
      (в bash-версии PID-reuse решено не чинить)
- [ ] GUI пока остаётся kdialog-обвязкой над новым CLI
- [ ] интеграционные тесты в CI на чистом WireGuard; AmneziaWG-специфика — юнитами
- [ ] bash-версия удаляется только после подтверждённого паритета на живой машине

## M2 — Песочница в ядре

- [x] `wl-sandbox.c` поглощён крейтом и удалён — C в проекте больше нет:
      `vpn-zone-core wl-sandbox <app-id> -- <кмд…>` (wayland-client +
      wayland-protocols, staging-протокол security-context). Проводной протокол
      wayland-client говорит сам, на Rust, — libwayland не линкуется. Поведение
      1:1 с прежней программой; тестами покрыты fallback-пути (без композитора
      программа обязана запуститься с предупреждением), сам ограниченный сокет
      проверяется руками на niri/KWin
- [ ] поглотить `vpn-fs-sandbox`: bwrap, разрешения, `/.flatpak-info`,
      dbus-прокси и xwayland-satellite — пока bash (seccomp-фильтр для него уже
      в крейте)
- [x] seccomp-фильтр по образцу flatpak (libseccomp → fd в `bwrap --seccomp`):
      TIOCSTI/TIOCLINUX, ptrace, keyring, `perf_event_open`, `personality`,
      новый mount-API и `clone3` (ENOSYS — чтобы libc уходила на старый путь).
      Вложенные user namespace по умолчанию НЕ запрещены: в NixOS нет zypak и
      setuid chrome-sandbox, поэтому Chromium и Electron строят свой userns и
      без него не стартуют вовсе — запрет есть отдельным флагом `--deny-userns`

## M3 — Сетевое ядро

Основа — архитектура из `docs/LEAK-MODEL.md`: связность живёт в uplink-ns,
приложения — в app-ns, где нет ничего, кроме lo и туннеля.

- [ ] абстракция «провайдер туннеля» (kernel WireGuard / AmneziaWG — первые два)
- [ ] зоны «через существующий интерфейс хоста»: pasta `--outbound-if4/--outbound-if6`
      / `--outbound <addr>` — зона без туннеля внутри, привязанная к выбранному
      интерфейсу (системный VPN, второй аплинк и т.п.)
- [ ] фаерволл: nftables внутри зоны — default-deny egress, разрешён только
      туннель; LAN — явной опцией; это же второй эшелон killswitch
- [ ] DNS: безопасный дефолт при пустом `DNS=`, опционально DoT/DoH через
      локальный резолвер зоны
- [ ] полноценный IPv6: маршрут в туннель, иначе blackhole (не «мимо туннеля»)
