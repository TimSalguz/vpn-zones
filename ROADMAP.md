# Роадмап vpn-zones

Цель: универсальный rootless-инструмент запуска программ в сетевых зонах
(VPN, прокси, существующие интерфейсы, офлайн) с контейнерами данных и
песочницами — с прицелом на публикацию в nixpkgs.

Ядро планируется переписать на Rust одним статическим бинарём: это открывает
seccomp (BPF-фильтр генерируется только кодом), настоящие тесты, поглощение
`wl-sandbox.c` и Python-скриптов, парсинг манифестов Flathub и структуру
«пакет + тонкий модуль», которую примут в nixpkgs. Переписывание — «стренглером»:
bash-версия остаётся рабочей до подтверждённого паритета. Спецификация
накопленного поведения — [docs/GOTCHAS.md](docs/GOTCHAS.md).

Приоритет №1 на всех этапах — герметичность: никаких утечек DNS, IPv6 и
трафика мимо туннеля, fail-closed по умолчанию. Пункты, закрывающие утечки
(killswitch-заплатки M0, фаерволл/DNS/IPv6 в M3, seccomp в M2, leak-тесты в
M5), имеют преимущество перед удобствами.

Порядок этапов — приоритет, а не жёсткая очередь: сетевые этапы (M3–M5) могут
идти параллельно песочнице (M2).

## M0 — Гигиена и фундамент (текущая bash-версия)

- [ ] README на английском, русский — `README.ru.md`
- [ ] `docs/GOTCHAS.md` — выгрузка граблей из комментариев (спецификация для переписывания)
- [ ] CI: `nix flake check`, shellcheck; каркас интеграционных тестов в unprivileged userns
- [ ] `CHANGELOG.md`, semver-теги релизов
- [ ] Багфиксы текущей версии:
  - [ ] IPv6 в конфигах: endpoint `[…]:port`, `Address` с v6-адресом (сейчас всюду `-4`)
  - [ ] конфиг без `DNS=`: зона остаётся с хостовым resolv.conf и имена молча не резолвятся — нужен безопасный дефолт или явная ошибка
  - [ ] блокировки (flock) на реестр запусков `.running` — гонки при параллельных стартах
  - [ ] PID-reuse в проверках живости (сравнивать starttime из `/proc/<pid>/stat`)
  - [ ] gc одноразовых контейнеров судит по каталогу реестра, а не по живым PID
  - [ ] `fsflag` используется до инициализации в ветке `tmpjoin` (работает только на bash ≥ 4.4)
- [ ] Killswitch-заплатка: отключать IPv6 внутри зоны (sysctl), пока v6 не заворачивается в туннель — см. M3

## M1 — Rust-ядро (паритет с bash-версией)

- [ ] один бинарь `vpn-zone`: конфиги (CRLF, пустые `I1`–`I5`, wg/awg-автодетект),
      жизненный цикл зоны (unshare/newuidmap, netlink, pasta), `run`/nsenter,
      реестр запусков с блокировками, overlay-профили (поглощает `vpn-profile-run.py`)
- [ ] GUI пока остаётся kdialog-обвязкой над новым CLI
- [ ] интеграционные тесты в CI на чистом WireGuard; AmneziaWG-специфика — юнитами
- [ ] bash-версия удаляется только после подтверждённого паритета на живой машине

## M2 — Песочница в ядре

- [ ] поглотить `wl-sandbox.c` (wayland-rs, security-context) и `vpn-fs-sandbox`
- [ ] seccomp-фильтр по образцу flatpak (libseccomp → fd в `bwrap --seccomp`):
      TIOCSTI/TIOCLINUX, ptrace, вложенные user namespaces и т.д.

## M3 — Сетевое ядро

- [ ] абстракция «провайдер туннеля» (kernel WireGuard / AmneziaWG — первые два)
- [ ] зоны «через существующий интерфейс хоста»: pasta `--outbound-if4/--outbound-if6`
      / `--outbound <addr>` — зона без туннеля внутри, привязанная к выбранному
      интерфейсу (системный VPN, второй аплинк и т.п.)
- [ ] фаерволл: nftables внутри зоны — default-deny egress, разрешён только
      туннель; LAN — явной опцией; это же второй эшелон killswitch
- [ ] DNS: безопасный дефолт при пустом `DNS=`, опционально DoT/DoH через
      локальный резолвер зоны
- [ ] полноценный IPv6: маршрут в туннель, иначе blackhole (не «мимо туннеля»)

## M4 — Userspace-протоколы и прокси

- [ ] backend на sing-box (кандидат; альтернатива — xray-core): VLESS/VMess/Reality,
      Shadowsocks, Trojan, Hysteria2 — собственный tun внутри зоны
- [ ] OpenVPN-backend (tun создаётся внутри userns, root не нужен)
- [ ] импорт по ссылкам: `vpn://` (Amnezia), `vless://`, `ss://`; подписки — исследовать
- [ ] цепочки зон (proxy over VPN) — исследовать

## M5 — Мониторинг и диагностика
